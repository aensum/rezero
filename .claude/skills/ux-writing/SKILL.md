# 리제로 UX 라이팅

앤섬 공통 UX 라이팅 체계(인터미 판 789, 2026-10-22)를 리제로의원에 맞게 옮긴 것이다. 회장님 지적은 늘 같은 꼴이었다 — **세션이 회장님께 설명하듯 풀어 쓴 말**("네가 나에게 설명하듯이 말하지 말고, 실제 사용자가 쓰는 보편적인 말로"), 판 기록·주석 말투가 화면으로 샘, 개발 용어, 같은 정보 두 번, 지시어. 피부과 의원이므로 여기에 **의료광고 금지 표현**이 더해진다. 브랜드 색·서체·로고는 리제로 디자인 시스템 스킬(`anthropic-skills:rezero-design-system`)을 따른다.

## 0. 순서

1. **쓰기 전** — 이 파일과 [용어 사전](../../../lib/ux-wording.mjs)을 읽는다. 같은 자리에 피부과·병원 홈페이지, 네이버 예약·카카오톡 채널이 실제로 쓰는 말을 떠올린다.
2. **쓰는 중** — 아래 1~6 규칙.
3. **쓰고 나서** — `npm run wording`(main과 갈라진 뒤 새로 쓴 화면 글만 뽑음). ✗는 고치고(맥락 확인 줄은 읽고 판단), △와 나머지 글도 7번 점검표로 한 줄씩 읽는다. `npm test`가 사전의 test 줄을 저장소 전체에서 막는다.
4. **보고** — 새로 만든 버튼·메뉴 이름과, 그대로 둔 글·사유를 보고에 적는다.
5. **회장님이 문구를 지적하면** — 고치는 PR에서 용어 사전에 한 줄 더한다(피하는 말·쓰는 말·자리·출처·회장님 말 원문). 낱말로 잡히면 `check: 'test'`(같은 PR에서 저장소 전체를 고쳐 테스트 통과), 맥락을 봐야 하면 `'review'`. **같은 지적이 두 번 나오면 이 스킬의 결함이다.**

## 1. 의료법·의료광고 — 가장 먼저

- 읽는 사람은 **피부 고민으로 찾아온 환자·예비 환자**다. 정보를 사실대로 전하고 결과를 약속하지 않는다.
- 쓰지 않는 말(사전 test 줄): 완치·효과 보장·100% 효과 / 최고·최초·유일·가장 ~·1위·No.1·독보적 / 부작용 없음·통증 없음·무통·흉터 없음·안전 보장 / 기적·특효·즉시 효과·단 1회로·영구 제거 / 시술 추천·AI 피부 진단.
- 맥락을 보는 말(사전 review 줄): 진단·처방·판정(의사 진료 안내 자리만), 최신·첨단·프리미엄, 전후 사진, 할인·무료·선착순(환자 유인), 후기·체험단(치료 경험담), 전문의·Dermatologist(확인된 자격의 직함만 — 비전문의는 Doctor·Physician·원장).
- 장비는 '보유 장비' + 정품·정량 같은 사실 나열. 결과가 사람마다 다르면 '결과는 개인에 따라 다를 수 있어요'를 붙인다.
- 사진·영상 안의 글도 같은 기준으로 본다(디자인 시스템 7장).

## 2. 누구의 말로 — 환자가 평소 쓰는 말

- 기능을 풀어 설명하는 만든 말 금지. 이미 굳은 말을 쓴다: 예약·상담 신청·진료 시간·오시는 길·전화 걸기·카카오톡 상담.
- 개발 용어 금지: 서버·데이터·iframe·링크 오류 코드. 사용자가 하는 일로 바꾼다.
- 앤섬 공통 말: 고치기→수정·변경 / 거두기→전송 취소·삭제 / 고르기→선택 / 기간 '달'→10월·12개월·월별 / 답 기다림→답변 필요 / 까닭·저절로·그만두기·끝내기·셌어요·단추·열쇠·갈래·거르기·짐작→사유·자동으로·취소·완료·집계했어요·버튼·키·분류·필터·추정 / Anthem·앵섬→AENSUM·앤섬.

## 3. 짧게 — 잡초 뽑기

- 빼도 뜻이 같은 낱말·문장은 뺀다. 같은 정보를 한 화면에 두 번 쓰지 않는다. 허전해서 붙이는 설명 문장 금지.
- **지시어(그날·그때·이번·이렇게·여기·이 기기) 금지** — 이름으로 쓰거나 뺀다("'그날'처럼 그 저 이 이런 말 쓰지 마!!!" — 인터미 판 777).
- 버튼·상태는 짧은 말 하나. 잘려도 앞부분만으로 뜻이 통하게 핵심어·숫자를 앞에.

## 4. 말투·표기

- **버튼·안내·오류·확인 창은 해요체**(…했어요·…해 주세요), 강요 대신 권유.
- **병원 소개 본문은 브랜드 말투(차분한 합쇼체)를 유지**한다 — 예) '완연한 관심으로 피부를 살핍니다'·'진료 전 충분한 상담이 먼저입니다'(디자인 시스템 1장). 의도된 브랜드 말투는 해요체로 바꾸지 않고, `npm run wording`의 합쇼체 △는 보고에 '브랜드 말투로 둠'이라 적는다.
- 맞춤법대로 띄어 쓴다(더 보기·바로 가기·진료 시간). 나열은 가운뎃점(레이저·리프팅), 중괄호·A/B·긴 괄호 덧붙임 금지.
- '잠시 뒤' 대신 구체적인 시간. 앤섬은 어느 언어에서도 AENSUM·앤섬.

## 5. 자리별 짜임

| 자리 | 짜임 | 예 |
|---|---|---|
| 버튼 | 동사 하나 — 누르면 무엇이 일어나는지 보이게 | 지금 예약하기·전화 걸기·자세히 보기 |
| 상태·배지 | 업무 상태 이름 | 예약 완료·답변 필요·휴진 |
| 빈 화면 | 무엇이 없는지 + 할 일 하나 | '예정된 예약이 없어요' + 예약하기 |
| 오류 | 무슨 일 + 할 수 있는 일, 탓하지 않기 | '예약을 보내지 못했어요. 1분 뒤 다시 시도해 주세요.' |
| 결과 알림 | 한 일 + 숫자, 되돌리기는 버튼 | '상담 신청을 보냈어요' |
| 확인 창 | 질문 + 결과 + 동사 버튼 | '예약을 취소할까요?' · 예약 취소 / 닫기 |
| 이미지 대체 글(alt) | 보이는 것을 사실대로, 효과 주장 없이 | '리제로의원 상담실' |

## 6. 다국어

- 한국어 원문을 위 규칙으로 다듬은 뒤 번역한다. 직역 대신 그 나라 병원·예약 앱이 같은 자리에 쓰는 말로. 의료광고 기준은 번역문에도 같다.

## 7. 내보내기 전 점검표 (새 글 한 줄마다)

1. 환자가 소리 내어 읽어도 자연스러운가?
2. 결과를 약속하거나 다른 병원보다 낫다고 말하지 않는가?
3. 내가 만든 말·개발 용어·지시어가 아닌가?
4. 빼도 뜻이 같은 낱말·문장, 같은 화면의 중복 정보가 없는가?
5. 버튼 이름만 보고 누르면 무슨 일이 생기는지 아는가?
6. 해요체(브랜드 본문은 합쇼체)·띄어쓰기·가운뎃점을 지켰나?
7. 휴대폰 폭에서 잘려도 앞부분으로 뜻이 통하나?

## 검사 범위

- `scripts/wording-scan.mjs`가 HTML 글·사람이 읽는 속성(alt·title·aria-label·placeholder·value·content)과 스크립트의 문자열·템플릿 조각·JSX 글을 뽑는다(주석·스타일 제외).
- 건너뛰는 곳은 `lib/ux-wording.mjs`의 `wordingSkip`(사전·검사 도구·스킬 문서). 법적 고지 원문·AI 지침·샘플이 생기면 그 파일을 여기에 더한다.
